# 磁碟轉換修正概要（完整版）

> 更新日期：2026-10-08
> 情境：專案資料夾從本機 APFS 磁碟搬到外接式磁碟 `/Volumes/Mobil`（檔案系統 **exFAT**，掛載選項含 `noowners`），專案路徑變成 `/Volumes/Mobil/**Git_Mobil/FileSyn`。
> 一句話結論：腳本本來就用 `dirname` 取得自身位置，**沒有寫死舊路徑**；搬家後的問題幾乎都來自 exFAT 的檔案系統特性，只有手冊索引的連結是真正寫死了舊的絕對路徑。

---

## 1. 根本原因：exFAT 與 APFS 的差異

| exFAT 的特性 | 後果 |
|---|---|
| 不支援擴充屬性（xattr） | macOS 會在每個帶 xattr 的檔案旁建立 AppleDouble 檔 `._<檔名>`。在 exFAT 上，它們看起來是「真實存在的檔案」，會被 `codesign`、`zip`、`ditto`、`gradle`、`git` 當成一般檔案處理。 |
| 不保存 Unix 權限與擁有者 | 所有檔案固定顯示為 `rwx------`，擁有者為目前使用者。打包成安裝檔後，其他使用者無法讀取。 |
| 不分大小寫 | `Scripts/` 與 `scripts/` 指向同一個資料夾（`ls` 會同時列出兩者）。目前沒有造成問題，但若 git 內同時存在兩種大小寫的路徑，需要留意。 |
| 路徑含特殊字元 | 上層資料夾名稱 `**Git_Mobil` 含有 `*`，任何沒加引號的 shell 變數或萬用字元展開都可能出錯。 |

## 3. 各項詳細說明

### 3.1 `codesign` 失敗：`Operation not permitted`

- **現象**：`Scripts/build-app.sh` 在簽署階段失敗，錯誤指向 `build/SyncNexus.app/Contents/MacOS/._SyncNexus`。
- **原因**：`.app` 直接組裝在 exFAT 上，可執行檔旁邊出現 `._SyncNexus`，`codesign` 拒絕處理。
- **解法**（[Scripts/build-app.sh](../Scripts/build-app.sh)）：
  1. `export COPYFILE_DISABLE=1`。
  2. 用 `mktemp -d` 在**本機磁碟**組裝 `SyncNexus.app` 並簽署（含 App Store 與 sandbox 模式）。
  3. 完成後 `ditto --norsrc --noextattr --noqtn` 複製到 `build/SyncNexus.app`。
  4. 對 `build/` 內的成品再執行一次 `codesign --verify --deep --strict`。
  5. `--install` 仍從暫存的 app 安裝到 `~/Applications`。

### 3.2 `Resources/` 內的 `._*` 被簽進 app

- **現象**：第一次修好後，複製回 `build/` 驗證失敗：`a sealed resource is missing or invalid`，缺的是 `ManualAssets/**/._*.png`。
- **原因**：`Resources/`（原始碼，未被 git 追蹤）本身有 `._*`，被 `cp -r` 複製進 app 並被簽章封存；後來把它們刪掉就破壞了封條。
- **解法**：複製 `ManualAssets` 改用 `rsync -a --exclude='._*' --exclude='.DS_Store'`，讓垃圾檔**從一開始就不進入 bundle**。
- **原則**：不要「事後刪除」已被簽章封存的檔案，要在簽署前就排除。

### 3.3 zip 內含 80 個 `._*`

- **現象**：`build/SyncNexus-<版本>.zip` 解開有 80 個 `._*`。
- **原因**：`ditto -c -k` 從 exFAT 讀取時，把 `._*` 當成真實檔案壓進去。
- **解法**（[Scripts/package.sh](../Scripts/package.sh)）：先 `rsync --exclude='._*'` 到本機暫存，再從暫存壓縮。
- **驗證**：zip 內 0 個 `._*`；解壓後 `codesign --verify` 通過。

### 3.4 DMG

- **解法**（[Scripts/package_macos_dmg.sh](../Scripts/package_macos_dmg.sh)）：`cp -R` 改成 `ditto --norsrc --noextattr --noqtn`，並設定 `COPYFILE_DISABLE=1`。
- **驗證**：掛載後 0 個 `._*`，app 簽章通過。

### 3.5 Android 打包

- **現象**：Gradle 失敗：`…/app/build/intermediates/packaged_res/release/packageReleaseResources/._mipmap-hdpi-v4 is not a directory`。
- **原因**：Gradle 自己在 exFAT 的 `build/` 中間產物旁產生 `._*`，只清除原始碼內的 `._*` 並不夠。
- **解法**（[Scripts/package_android.sh](../Scripts/package_android.sh)）：
  - 把 `Platforms/Android` 複製到本機暫存目錄（排除 `._*`、`build/`、`.gradle/`）建置，再把 APK／AAB 複製回 `dist/`。
  - 簽署金鑰 `release-key.jks` 以相對路徑 `../release-key.jks` 參照，專案本身不依賴 `Platforms/Android` 以外的檔案，所以複本可直接建置。
  - 自動偵測 Android SDK（`~/Library/Android/sdk`）與 Homebrew 的 JDK 17。
  - 找不到 gradle／SDK 時改為印出警告：「以下僅是原始碼壓縮檔，不是可安裝的 APK/AAB」（原本會默默產出）。
- **驗證**：`BUILD SUCCESSFUL`；APK 含 `classes.dex` 與 `AndroidManifest.xml`；`apksigner verify` 簽章有效；APK、AAB 內 0 個 `._*`。

### 3.6 App Store Connect 錯誤 90255

- **完整訊息**：The installer package includes files that are only readable by the root user. This will prevent verification of the application's code signature when your app is run.
- **原因**：exFAT 把所有檔案標成 `rwx------`，`productbuild --component` 照原樣把權限包進 pkg，安裝後非 root 使用者讀不到。
- **解法**：
  - 新增 [Scripts/lib-pkg.sh](../Scripts/lib-pkg.sh)：
    - `stage_app_for_pkg`：複製 app 到本機暫存，排除 `._*` 與 `.DS_Store`，目錄 755、檔案 644、`Contents/MacOS` 內執行檔 755。只改權限，不影響簽章。
    - `check_pkg_readable`：打包後 `pkgutil --expand-full` 展開，若有 `._*` 或非全員可讀的檔案就報錯中止。
  - [Scripts/package_macos_app_store.sh](../Scripts/package_macos_app_store.sh) 與 [Scripts/package-appstore.sh](../Scripts/package-appstore.sh) 改為從暫存複本執行 `productbuild` 並呼叫檢查。
- **驗證**：重新產出的 pkg 展開後，非全員可讀檔案 0 個、`._*` 0 個、`codesign --verify` 通過。
- **踩雷**：macOS 內建的 `rsync`（openrsync）**不支援 `--chmod`**，所以權限改用 `find … -exec chmod`。
- **尚未確認**：實際上傳到 App Store Connect 後是否通過伺服器端驗證（只做了本機檢查）。

### 3.7 手冊與隱私權政策索引的絕對連結

- **現象**：索引檔的連結寫死舊位置，例如 `file:///Users/barretlin/GitProjects/FileSyn/docs/manual/...`。這是唯一真正「寫死舊路徑」的地方。
- **解法**：全部改成相對於各檔案所在目錄的相對路徑。涉及 6 個檔案：
  - `docs/MANUAL.md`、`docs/PRIVACY_POLICY.md`
  - `packaging/appstore/MANUAL.md`、`packaging/appstore/PRIVACY_POLICY.md`
  - `packaging/googleplay/MANUAL.md`、`packaging/googleplay/PRIVACY_POLICY.md`
- **驗證**：所有連結目標都存在；`Scripts/check_i18n.sh` 通過。

### 3.8 `.gitignore`

- 新增 `._*`，避免 AppleDouble 檔被誤加入版本控制。

### 3.9 `.git` 內的 `._*` 與 git 警告

- **現象**：每個 git 指令都印出多行 `error: non-monotonic index .git/objects/pack/._pack-*.idx`。
- **原因**：`.git` 內共有 1441 個 `._*`（包含 `._config`、`._objects`、`._pack-*.idx` 等），git 把 `._pack-*.idx` 當成套件索引讀取。
- **解法**：`find .git -name '._*' -type f -delete`。
- **驗證**：`git fsck` 無錯誤、警告消失，之後的提交與推送正常。
- **注意**：macOS 之後可能在 exFAT 上重新產生這些檔案，若警告再次出現，重跑同一行指令即可。

### 3.10 Android 假成品問題

- 見 3.5。這是既有的設計缺陷（退回模式產出的是原始碼壓縮檔），在新環境找不到 SDK 時特別容易誤用，所以一併加上警告。

### 3.11 `git status` 滿是「已修改」的檔案

- **現象**：`git status` 列出約 360 個已修改檔案（`docs/`、`LICENSE`、`Package.swift`、圖片等），但內容完全沒變。`git diff` 只顯示 `old mode 100644 / new mode 100755`。
- **原因**：exFAT 不保存權限，所有檔案都顯示為 `rwx`，git 因此認為每個檔案都被改成可執行。
- **解法**：對這個 repo 設定 `git config core.fileMode false`（只影響本機 `.git/config`，不會推送）。
- **驗證**：設定後 `git status` 只剩真正有內容變更的檔案（約 6 個）。
- **注意**：此設定只在這個 clone 內有效；若重新 clone 到 exFAT，需要再設定一次。腳本的可執行權限仍以 git 內記錄的為準。

## 6. 保留事項

- **Homebrew cask**：`packaging/homebrew/syncnexus.rb` 的 `sha256` 是範本佔位值，**刻意不填**。它必須是「已上傳到 GitHub Release 的那個 zip」的雜湊，而每次重建 zip 的雜湊都不同。發布時請把 `Scripts/package.sh` 輸出的 sha256 與版本填入。
- **版本號**：`VERSION` / `BUILD_NUMBER` 與打包腳本的產出檔名有關。`package_android.sh` 會用 `sed` 改寫 `Platforms/Android/app/build.gradle.kts` 的 `versionCode`／`versionName`，該檔案在工作區本來就有未提交的修改，提交時需要自行檢查。
- **`Resources/` 內的 `._*`**：不受 git 追蹤、仍留在磁碟上。目前由 `rsync --exclude` 在打包時略過，不影響成品，可視需要自行清除。

## 7. 日後在 exFAT 上工作的守則

1. **不要直接簽署或打包 exFAT 上的 `.app`**：一律先複製到本機磁碟（腳本已自動處理）。
2. 複製 bundle 一律加 `--norsrc --noextattr` 或排除 `._*`，不要事後刪除已被簽章封存的檔案。
3. 不要依賴檔案權限（一律 `rwx------`）；要發布的安裝檔必須從標準權限的複本產生。
4. 路徑含 `**`：shell 腳本中的路徑變數**一律加雙引號**，避免未加引號的萬用字元展開。
5. 看到 `._*` 相關的錯誤時，先判斷它來自「原始碼」、「建置工具的中介產物」還是「`.git`」，三者的處理方式不同（排除、改在本機建置、刪除）。
6. 根本解法：若不需要隨身攜帶，把專案放回本機 APFS；或把外接磁碟重新格式化為 APFS，上述問題都不會發生。
