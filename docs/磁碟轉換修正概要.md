# 磁碟轉換修正概要

> 日期：2026-10-07
> 背景：專案資料夾從本機 APFS 磁碟移到外接式磁碟 `/Volumes/Mobil`（**exFAT**，`noowners`），專案路徑變成 `/Volumes/Mobil/**Git_Mobil/FileSyn`。
> 結論：打包腳本本來就用 `dirname` 取得自身位置，**沒有寫死舊路徑**；真正的問題全部來自 exFAT 的檔案系統特性。

## exFAT 帶來的兩個根本差異

| 特性 | 影響 |
|---|---|
| 不支援擴充屬性（xattr） | macOS 會在每個帶 xattr 的檔案旁邊建立 AppleDouble 檔 `._<檔名>`。這些檔案在 exFAT 上看起來是「真實檔案」。 |
| 不保存 Unix 權限 | 所有檔案固定顯示為 `rwx------`（只有擁有者可讀寫執行）。 |

## 問題與解法

### 1. `codesign` 失敗：`Operation not permitted`

- **現象**：`Scripts/build-app.sh` 簽署時報錯，指向 `build/SyncNexus.app/Contents/MacOS/._SyncNexus`。
- **原因**：`.app` 直接組裝在 exFAT 上，二進位檔旁邊出現 `._SyncNexus`，`codesign` 拒絕處理。
- **解法**：[Scripts/build-app.sh](../Scripts/build-app.sh) 改成在**本機暫存目錄**（`mktemp -d`）組裝並簽署，完成後用 `ditto --norsrc --noextattr --noqtn` 複製回 `build/`，並再驗證一次簽章。同時 `export COPYFILE_DISABLE=1`。

### 2. 原始碼的 `Resources/` 內有 `._*` 垃圾檔，被簽進 app

- **現象**：第一次修正後，複製回 `build/` 時 `codesign --verify` 回報 `a sealed resource is missing or invalid`，缺的檔案是 `ManualAssets/**/._*.png`。
- **原因**：`Resources/` 本身就有 `._*` 檔，被 `cp -r` 複製進 app 並被簽章封存；之後把它們刪掉就破壞了封條。
- **解法**：複製 `ManualAssets` 時改用 `rsync -a --exclude='._*' --exclude='.DS_Store'`，讓垃圾檔**一開始就不進入 bundle**，而不是事後刪除。

### 3. zip 內含 80 個 `._*` 檔

- **現象**：`build/SyncNexus-<版本>.zip` 解開有 80 個 `._*` 項目。
- **原因**：`ditto -c -k` 從 exFAT 讀取時，把 `._*` 當成真實檔案一起壓縮。
- **解法**：[Scripts/package.sh](../Scripts/package.sh) 先用 rsync 排除 `._*` 複製到本機暫存，再從暫存壓縮。驗證：zip 內 0 個 `._*`，解壓後簽章通過。

### 4. DMG 打包

- **解法**：[Scripts/package_macos_dmg.sh](../Scripts/package_macos_dmg.sh) 以 `ditto --norsrc --noextattr --noqtn` 取代 `cp -R`，並設定 `COPYFILE_DISABLE=1`。驗證：掛載後 0 個 `._*`，簽章通過。

### 5. Android 打包

- **現象**：實際執行後 Gradle 失敗：`…/app/build/intermediates/…/._mipmap-hdpi-v4 is not a directory`。
- **原因**：Gradle 自己在 exFAT 上的 `build/` 中間產物旁產生 `._*`，打包前先清除原始碼內的 `._*` 並不夠。
- **解法**：[Scripts/package_android.sh](../Scripts/package_android.sh) 改成把 `Platforms/Android` 複製到**本機暫存目錄**（排除 `._*`、`build/`、`.gradle/`）建置，再把 APK／AAB 複製回 `dist/`。另外自動偵測 Android SDK（`~/Library/Android/sdk`）與 Homebrew 的 JDK 17。
- **附帶修正**：找不到 gradle／SDK 時，原本會默默產出「原始碼壓縮檔但副檔名是 .apk/.aab」；現在會明確印出警告，避免誤把它當成可安裝的成品。
- **驗證**：`BUILD SUCCESSFUL`；APK 含 `classes.dex` 與 `AndroidManifest.xml`，`apksigner verify` 簽章有效；APK、AAB 內 0 個 `._*`。

### 6. App Store Connect 錯誤 90255：檔案只有 root 可讀

- **現象**：上傳 pkg 時被拒，訊息為「The installer package includes files that are only readable by the root user」。
- **原因**：exFAT 把所有檔案標成 `rwx------`，`productbuild --component` 照原樣把這些權限包進安裝套件。
- **解法**：
  - 新增 [Scripts/lib-pkg.sh](../Scripts/lib-pkg.sh)：
    - `stage_app_for_pkg`：複製 app 到本機暫存、排除 `._*`，目錄設為 755、檔案設為 644、`Contents/MacOS` 內執行檔設為 755（只改權限，不影響簽章）。
    - `check_pkg_readable`：打包後展開 pkg，若發現 `._*` 或非全員可讀的檔案就報錯中止。
  - [Scripts/package_macos_app_store.sh](../Scripts/package_macos_app_store.sh) 與 [Scripts/package-appstore.sh](../Scripts/package-appstore.sh) 改為從暫存複本執行 `productbuild`，並在最後呼叫檢查。
- **驗證**：展開重新產出的 pkg，非全員可讀檔案 0 個、`._*` 0 個、app 簽章驗證通過。
- **踩雷**：macOS 內建的 `rsync`（openrsync）**不支援 `--chmod`**，因此權限改用 `find ... -exec chmod`。

### 7. 手冊與隱私權政策索引的絕對連結

- **現象**：6 個索引檔的連結寫死舊位置，例如 `file:///Users/barretlin/GitProjects/FileSyn/docs/manual/...`，搬家後全部失效。
- **解法**：全部改為相對路徑（依檔案所在目錄計算）。涉及檔案：
  - `docs/MANUAL.md`、`docs/PRIVACY_POLICY.md`
  - `packaging/appstore/MANUAL.md`、`packaging/appstore/PRIVACY_POLICY.md`
  - `packaging/googleplay/MANUAL.md`、`packaging/googleplay/PRIVACY_POLICY.md`
- **驗證**：所有連結目標存在；`Scripts/check_i18n.sh` 通過。

### 8. `.gitignore`

- 新增 `._*`，避免 AppleDouble 檔被誤加入版本控制。

## 日後在 exFAT 上工作的注意事項

1. **不要直接簽署或打包 exFAT 上的 `.app`**，一律先複製到本機磁碟（本專案腳本已自動處理）。
2. 複製 bundle 一律加 `--norsrc --noextattr` 或排除 `._*`，不要事後刪除已被簽章封存的檔案。
3. 資料夾名稱含有 `**`，在 shell 腳本中**務必為路徑變數加雙引號**，並避免未加引號的萬用字元展開；在 zsh 中直接對該路徑使用 `--include=*.sh` 之類的參數也可能因 glob 失敗。
4. 在 exFAT 上不能依賴檔案權限（一律 `rwx------`）。

## 後續處理結果

- **Git 套件索引警告**：已刪除 `.git` 內 1441 個 `._*` 檔案（含 `._pack-*.idx`）。`git fsck` 無錯誤，`non-monotonic index` 警告消失。
- **`Scripts/` 內的 `._*` 未追蹤檔**：已清除（且已被 `.gitignore` 忽略）。
- **Android 打包**：已實際執行並驗證，見上方第 5 項。
- **Homebrew cask**：`packaging/homebrew/syncnexus.rb` 的 `sha256` 維持範本佔位值，**刻意不填**。該值必須是「已上傳到 GitHub Release 的那個 zip」的雜湊，而每次重建 zip 的雜湊都不同；發布時請用 `Scripts/package.sh` 輸出的值填入。
- **建議**：若不需要隨身攜帶，將專案放回本機 APFS 磁碟，可從根本避免上述所有問題；外接磁碟可重新格式化為 APFS 以取得相同效果。
- **提醒**：macOS 之後仍會在 exFAT 上重新產生 `._*`（包含 `.git` 內），若警告再次出現，可再執行 `find .git -name '._*' -type f -delete`。
